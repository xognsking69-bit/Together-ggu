# Togetrip 시간 절약 상품 준비 — 2026-10-17

상태: 기존 앱 3.28.29 소스 후보. 운영 배포·스토어 상품 등록·가격 확정 없음.

## 결정

첫 판매 후보는 영수증 자동 입력 무료 체험 + 횟수권이다. 기본 수동 입력·정산·공동 여행은 무료 유지한다. 광고 제거는 우선순위에서 내리고 기존 준비 코드는 비활성으로 둔다. 광고를 늘려 구매를 유도하지 않는다.

## 소스에서 확인한 현재 기능

- receipt-tools: 사진 선택·관리 복사, 인식 결과 입력 폼 반영, 사용자가 지출 저장.
- receipt-ai-worker: 서명된 게스트 세션, 무료 5회, 일별/전체 한도, 서버 추론. Cloudflare AI 경로와 외부 API 대체 경로가 존재한다. 실제 운영 제공자 설정·청구액은 이번에 확인하지 않았다.
- 기기 내 OCR은 아직 없다. iOS Vision / Android ML Kit 등 기기 내 인식으로 충분한지 기술 검증이 먼저다. 이를 구현 완료 또는 무조건 비용 0이라고 보고하지 않는다.
- 게스트 사용량은 보존 기간 후 alarm에서 삭제된다. 이 저장소를 유료 잔액이나 영구 무료 체험 이력으로 재사용하지 않는다.
- 현재 무료 흐름은 성공 뒤 사용량 확정이며, 서로 다른 사용량 객체의 순차 확정이다. 네트워크 중단 시 원자적 결제가 보장되지 않는다.
- 서버가 처리했으나 응답을 잃은 재시도에 대한 영구 멱등 기록이 없다. 이 상태로 유료 횟수를 차감하면 안 된다.
- 구매 SDK 설치 및 광고 제거 비활성 코드와 영수증 유료 횟수권 판매 완료는 별개다. 유료 영수증 구매·복원·소비 원장은 미구현이다.
- 현재 다운로드·활성이용자·건당 비용·광고 매출을 새로 조회하지 않았다. 과거 수치로 현재 수익을 확정하지 않는다.

## 이번 코드 수정

금액이 없거나 0 이하이거나 통화가 불명확한 결과는 RECEIPT_UNREADABLE / HTTP 422로 응답하고 무료·일일·전체 예약을 해제한다. JSON 파싱 성공만으로 차감하지 않는다. 이 규칙은 공급자 호출 비용까지 없애주지 않는다. 판독 정확성을 보장하거나 유료 거래 원장을 구현한 것은 아니다.

## 유료 상품의 필수 처리 계약

1. 가격/횟수는 승인 후 결정, 화면 가격은 스토어 응답 사용. 서버 허용 상품 목록과 거래 검증으로 지급 수량 결정. 클라이언트가 보내는 가격·횟수를 신뢰하지 않는다.
2. App Store/Google Play 거래를 서버 검증하고 플랫폼+거래 ID 고유키로 한 번만 지급. 환불·취소 알림도 같은 원장에 기록한다.
3. 사용자 계정과 재설치·기기 변경 시 복구 수단을 먼저 확정한다. 현재 게스트 키만으로 유료 잔액을 보장하지 않는다. 소모성 상품의 스토어 복원만으로 이미 소비된 잔액이 복구된다고 약속하지 않는다.
4. 분석 요청은 requestId와 이미지 해시로 중복 제어. 동일 요청 재전송은 동일 상태/결과 반환. 임의 해시만으로 다른 사용자 결과를 노출하지 않는다.
5. 한 원자적 원장에서 예약 → 성공 확정 또는 실패 해제. 병렬 요청으로 잔액이 음수가 되거나 한 요청이 두 번 차감되지 않아야 한다. 시간 초과는 작업 상태 조회로 복구한다.
6. 금액·통화 판독 불가/서비스 오류는 차감하지 않는다. 사용 가능한 결과 전달 시 1회 사용이며 지출 저장·수정은 추가 차감 없음. 이미 전달된 정상 결과를 사용자가 취소하는 경우 정책을 화면에 명확히 안내한다.
7. 무료/유료 잔액을 구분하고 만료 없는 구매 크레딧을 기본 설계한다. 환불 뒤 잔액 조정·이미 소비된 거래 처리는 고지와 스토어 정책 검토 후 확정한다.
8. 결과 확인 화면에서 원본과 금액·통화·날짜·가맹점을 수정하고 저장한다. 날짜·가맹점 추정값을 확정 사실처럼 표시하지 않는다.

## 개인정보

기기 내 처리를 우선 조사한다. 원격 분석은 업로드 전 제공자·목적·보관 범위를 안내한다. 이 서버 코드의 영구 이미지 저장 부재가 공급자의 무보관 보장은 아니다. 이미지/추출 본문을 로그에 남기지 않고 공급자 보존·삭제 정책을 확인한다. 비용 측정에는 익명 요청 ID·처리시간·상태·사용량만 사용한다. 샘플은 합성 영수증 또는 명시적 동의를 받은 비식별 자료만 사용한다.

## 첫 개발 단계와 완료 기준

다음 단계는 판매 연결보다 기기 내 OCR 기술 검증과 품질 측정이다. 한국어·영어·일본어 합성 영수증 최소 30장(언어별 10장, 합계/소계/통화 혼동 포함)으로 직접 입력 대비 시간·수정 수·금액/통화 정확 일치·실패율·처리시간을 기록한다. 목표 가설은 중앙 입력시간 30% 이상 단축, 금액/통화 정확 일치 95% 이상, 읽지 못한 경우 오입력 확정 0건이다. 달성 여부는 아직 측정하지 않았다. 실제 iOS/Android에서 확인 전 출시 가능 판정을 하지 않는다.

횟수권 구현 착수 전: 영구 계정/복구 방식, 원장 스키마, 서버 거래 검증, 중복 요청·병렬·응답 유실·환불 테스트 계획 검토. 판매 전: 양 플랫폼 샌드박스 결제/취소/재설치·복원/환불, 사용자 안내, 개인정보 표시, 예상 비용과 가격 승인 필수.

## 손익 판단 — 금액 미확정

횟수권 순이익 = 실제 스토어 정산금 - 성공/실패/재시도 전체 추론 비용 - 저장·전송·결제 연동 비용 - 지원·환불 비용.
스토어 수수료율은 계정 프로그램/국가/세금 조건 확인 없이 15% 등으로 고정하지 않는다. 실제 청구 단위·무료 한도·한도 초과 정책이 확인되기 전 무제한/평생 AI를 판매하지 않는다. 새 외부 유료 서비스·월정액 가입 없음.

## 역할과 실행 경계

- 개발: 현재 수동 실행으로 코드·테스트·샘플 검증 기록. 검증 자료가 사업 담당에게 전달되어야 가격 제안 가능.
- 사업: 건당 비용·절약 시간·반복 사용 근거로 가격안 비교. 판매 대상 확정 전 개발 검토 필요.
- 홍보: 검증된 출시 기능만 소개. 초안 작성은 가능, 외부 게시·발송은 승인 필요.
- 총괄: 주간 검토 시 근거/차단사항 통합. 이번에 예약 작업이나 백그라운드 에이전트를 연결하지 않았다.
- 사용자: 비용 도입·상품 가격/범위·스토어 제출·배포를 승인. 운영 데이터 수정 없음.
